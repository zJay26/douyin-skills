# douyin-skills v1.4.0

`v1.4.0` adds guarded video publishing and hardens the page-evidence rules for
like/favorite toggles and authenticated sessions that carry stale risk-page
clues.

## What's included

- `fill-publish-video` uploads one local video, waits for durable upload-ready
  evidence, and applies exact title and description values.
- `set-video-cover` opens the current Creator Center cover editor, uploads a
  local custom cover, completes the vertical-cover flow, and confirms that the
  publish form exposes a selected cover.
- `validate-publish-video` separately checks video evidence, title,
  description, cover, optional topic, and the publish button without clicking
  publish.
- `click-publish-video --confirm` requires the media-specific validation and
  preserves the existing confirmed versus clicked-but-unconfirmed result
  boundary.
- Like and favorite actions now require explicit adapter-declared active or
  inactive state evidence before a toggle click. Unknown or conflicting state
  returns a safe stop without probing the control.
- Login handling rechecks the visible browser after a headed transition and
  does not treat a stale risk title as a persistent verification page when the
  current authenticated UI disproves it.

## Install or upgrade

With OpenClaw:

```bash
openclaw skills install git:zJay26/douyin-skills@v1.4.0
```

For a manual checkout:

```bash
git fetch --tags
git checkout v1.4.0
npm ci
python scripts/cli.py doctor
```

If you use the GitHub Release, download `douyin-skills-v1.4.0.zip` and
`SHA256SUMS`, verify the checksum, and extract the package into a new
directory. Local account data remains outside the repository by default and
must not be copied into a release package.

## Validation scope

The release gate covers 107 Python unit tests, 19 privacy-safe synthetic
fixtures, repository integrity validation, the 960×540 privacy-safe Demo,
Node.js syntax and CDP tests, Ruff lint and format checks, and a reproducible
release build.

The dated live smoke run on 2026-08-25 reconfirmed a reused logged-in Chrome
session without a persistent risk page. A synthetic one-second MP4 and custom
cover reached `fill-publish-video` status `filled`, followed by
`validate-publish-video` state `ready` with no errors. The temporary form was
closed and no publish click was issued.

These checks validate the result contract and the observed environment. They
do not guarantee current compatibility for every account, video/note page,
selector version, captcha, interaction, or publishing flow.

## Boundaries

- Only the Douyin adapter ships in this release.
- Comment replies, direct messages, draft management, scheduling, and bulk
  operations remain unsupported.
- Fixtures are synthetic and privacy-safe; they are not captured HTML or live
  page evidence.
- Captcha, identity checks, and risk controls are surfaced for human handling
  and are never bypassed.
- Photo and video publishing both require media-specific validation and a
  separate explicit confirmation.
- `publish_clicked_unconfirmed` and unverified interaction state must never be
  retried automatically or reported as confirmed.
- No account, session, profile, QR code, phone number, or private-content data
  is included in the release package.
