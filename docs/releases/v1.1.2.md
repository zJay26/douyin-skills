# douyin-skills v1.1.2

`v1.1.2` adds a focused way to rerun synthetic page-state regressions when a
page-drift report identifies one workflow or one certainty boundary. The
validator can still run the complete fixture set, while maintainers can now
target a workflow with `--flow` or one stable fixture with `--fixture-id`.

The release keeps the existing Douyin-only adapter, JSON result contract,
browser lifecycle, human-verification policy, and publish confirmation gates
unchanged.

## What's included

- `python scripts/validate_fixtures.py --flow detail` for all detail-state
  regressions.
- `python scripts/validate_fixtures.py --fixture-id detail-page-drift` for one
  reproducible route-drift case.
- Synthetic detail fixtures for verification-risk and unavailable-content
  outcomes, with schema, URL, expected-result, and privacy validation.
- Unit coverage for fixture selection, focused CLI runs, and unknown-filter
  failure behavior.

## Install or upgrade

With OpenClaw:

```bash
openclaw skills install git:zJay26/douyin-skills@v1.1.2
```

For a manual checkout:

```bash
git fetch --tags
git checkout v1.1.2
npm ci
python scripts/cli.py doctor
```

If you use the GitHub Release, download `douyin-skills-v1.1.2.zip` and
`SHA256SUMS`, verify the checksum, and extract the package into a new
directory. Local account data remains outside the repository by default and
must not be copied into a release package.

## Validation scope

The final release commit is gated by the repository's Python, Node.js, fixture,
packaging, lint, formatting, and documentation-integrity checks. The feature
PR passed the Windows (Python 3.13 / Node.js 24) and Ubuntu (Python 3.9 /
Node.js 18) CI matrix, plus Ruff, before merge.

The release evidence includes 60 Python unit tests, 13 privacy-safe synthetic
fixture validations, focused detail and single-fixture runs, repository
integrity validation with the 960×540 40-second Demo, one Node.js CDP bridge
test, Ruff lint/format checks, two reproducible release builds, and a
fresh-extraction version smoke test.

These checks validate fixture semantics, selection behavior, documentation,
and release packaging. They do not prove current live-page compatibility for
every account, selector version, captcha, interaction, or publishing flow.

## Boundaries

- Only the Douyin adapter ships in this release; no second platform is
  implemented or advertised.
- Fixtures are synthetic and privacy-safe; they are not captured HTML or live
  page evidence.
- Focused validation does not weaken schema, expected-result, URL, or privacy
  checks; it only relaxes the all-workflow coverage requirement for the
  selected run.
- Existing human review rules and confirmed/unconfirmed result semantics
  remain in force.
- The release package contains repository files only and no account, session,
  profile, or private-content data.
